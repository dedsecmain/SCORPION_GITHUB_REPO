# Scorpion MK22 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Scorpion MK22 as a Windows-first, local-first desktop assistant with High German voice, barge-in, structured long-term memory, approval-gated Google Drive sync, continuous local screen context, trusted-app automation, risk-gated actions, improved local model routing, and a signed v22.0.0 self-update release.

**Architecture:** Keep the existing Scorpion Mk III modules as the foundation, but split new responsibilities into focused services: `long_term_memory.py`, `drive_sync.py`, `app_trust.py`, `action_policy.py`, `screen_context.py`, and `model_router.py`. `app.py` remains the composition root and wires these services into the existing voice, HUD, updater, and controller flow without moving sensitive or persistent state into cloud services by default.

**Tech Stack:** Python 3.12, pytest, CustomTkinter, sounddevice, faster-whisper, WebRTC VAD, edge-tts, pyttsx3, pygetwindow, OpenCV/Pillow, psutil, cryptography/Ed25519, Ollama/local models, Google Drive API with OAuth, GitHub Actions on Windows.

**Spec:** `docs/superpowers/specs/2026-09-14-scorpion-mk22-design.md`

## Global Constraints

- Product name: **Scorpion MK22**.
- Technical version: **v22.0.0**.
- Local-first operation remains the default.
- Paid cloud AI calls remain behind explicit per-use approval.
- Mutating and critical computer actions require confirmation before execution.
- Screen understanding may run continuously and locally.
- Raw screen captures, audio, secrets, tokens, passwords, cookies, and full unfiltered chat logs are never uploaded automatically.
- Memory is local-first and Google Drive sync is item- or project-level only after explicit approval.
- Large model downloads require user approval.
- Updates remain signed with Ed25519, SHA-256 verified, user-approved, self-checked, and rollback-capable.
- Private release signing keys never enter the public repository.
- Every implementation task follows RED → GREEN → REFACTOR with targeted tests before code.
